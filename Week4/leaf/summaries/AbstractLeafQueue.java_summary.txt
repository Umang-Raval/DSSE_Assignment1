**Unified Semantic File-Level Summary**

**Architectural Overview**

* **Component:** Leaf Queue Manager
* **Subsystem:** Resource Management & Scheduling (within a larger Distributed Computing Framework, likely Apache Hadoop YARN)
* **Layer:** Application/Service Layer (above the Resource Management Layer)
* **Responsibility:** Manages resource allocation, application lifecycle, and scheduling within a specific queue, ensuring adherence to scheduling policies, user limits, and queue capacities.

**Key Functionalities**

1. **Resource Management:**
	* Allocates, deallocates, and tracks resources (CPU, memory) for containers/applications.
	* Updates user/resource metrics, headroom, and queue statistics.
2. **Application Management:**
	* Handles application lifecycle events (activation, deactivation, completion).
	* Tracks application attempts, states, and resource usage.
3. **Scheduling Policy Enforcement:**
	* Orders schedulable entities (applications) for execution based on defined policies.
	* Respects user limits, queue capacities, and partition exclusivity.

**Core Logical Elements**

1. **Resource Allocation/Deallocation:**
	* `allocateResource` / `releaseResource`: Manage resource assignments for containers/applications.
2. **User Resource Usage Tracking:**
	* `updateUserResourceUsage`: Tracks changes in user resource utilization.
3. **Queue State Management:**
	* `stopQueue` / `updateQueueState`: Manage the queue's lifecycle (stopping, draining).

**Inputs and Outputs**

* **Inputs:**
	+ `SchedulerApplicationAttempt` objects
	+ `RMContainer` objects
	+ Resource updates (e.g., `incUsedResource`, `decUsedResource`)
	+ Configuration settings (e.g., capacity, max applications per user)
	+ `queueContext` and its `configuration`
	+ User management data
* **Outputs:**
	+ Updated resource allocations
	+ Application state changes
	+ Calculated pending resources
	+ Updated queue state
	+ Calculated maximum applications and per-user limits
	+ Preemption metrics
	+ Eligibility for auto-deletion
